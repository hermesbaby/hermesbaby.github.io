# Internationalization (i18n)

Hermesbaby can build your documentation in several languages. It uses the standard Sphinx
workflow based on [gettext](https://www.sphinx-doc.org/en/master/usage/advanced/intl.html):
the source text stays in one language, translatable messages are extracted into catalogs, and
translators fill in the catalogs. Each language is then built from the same sources.

This page walks you through the workflow from a fresh `zero` template to a translated build. It
follows the same sequence that Hermesbaby's own end-to-end test (`tests/e2e/test-i18n.bats`)
exercises.

## The workflow at a glance

| Step | Command                                   | Result                                                      |
|------|-------------------------------------------|-------------------------------------------------------------|
| 1    | `hb new`                                  | A new project from the `zero` template                      |
| 2    | `hb configure`                            | Languages and locale directory are set                      |
| 3    | `hb i18n gettext`                         | Check that message extraction works (`.pot` files)          |
| 4    | `hb i18n update-po`                       | Translation catalogs (`.po` files) are created or refreshed |
| 5    | edit the `.po` files                      | Translations are added                                      |
| 6    | `hb i18n stats` / `hb i18n stats-summary` | Translation coverage is reported                            |
| 7    | `hb html -l <language>`                   | The documentation is built in one language                  |

## 1. Create a project from the template "zero"

```bash
hb new my-docs
cd my-docs
```

`zero` is the default template. You can name it explicitly with `hb new -t zero my-docs`, and
list the available templates with `hb new --list-templates`.

Check that the untranslated documentation builds before you add translations:

```bash
hb html
```

## 2. Configure the languages

Run the configuration UI in the project directory:

```bash
hb configure
```

The settings are stored in the `.hermesbaby` file. Three of them matter for i18n:

| Setting             | Meaning                                                                                                          |
|---------------------|------------------------------------------------------------------------------------------------------------------|
| `DOC__LANGUAGE`     | The language the documentation is built in by default                                                            |
| `I18N__LANGUAGES`   | Comma-separated list of languages you translate into, for example `en,de`                                        |
| `I18N__DIR_LOCALES` | Directory for the translation catalogs, relative to the source directory. The test project uses `docs/_locales`. |

Setting `I18N__LANGUAGES` is optional: you can also pass the languages on the command line in
step 4.

## 3. Extract the translatable messages

```bash
hb i18n gettext
```

This runs the Sphinx `gettext` builder and writes one `.pot` template per document into the
`gettext` folder of the build directory, for example `out/docs/gettext/index.pot`. It does not
touch any `.po` file.

Use it as a diagnostic: it shows whether extraction works and surfaces warnings, such as
documents that are not part of any toctree.

## 4. Create the translation catalogs

```bash
hb i18n update-po -l en -l de
```

`update-po` extracts the messages again and then creates or updates one `.po` catalog per
language and document:

```text
docs/_locales/en/LC_MESSAGES/index.po
docs/_locales/de/LC_MESSAGES/index.po
```

Pass `-l` once per language. Without `-l`, Hermesbaby uses `I18N__LANGUAGES`. If neither is
given, the command stops with an error.

## 5. Translate

Open a `.po` file and fill in the empty `msgstr` entries. A catalog entry looks like this:

```text
msgid "This is a paragraph to translate."
msgstr "Dies ist ein Absatz zum Uebersetzen."
```

`msgid` is the original text and must not be changed. `msgstr` is the translation. Entries
marked `#, fuzzy` are guesses that need review. Remove the marker once you have checked them.
Any `.po` editor, for example Poedit, works as well.

## 6. Keep catalogs up to date

When the source documents change, run `update-po` again:

```bash
hb i18n update-po -l en -l de
```

Existing translations are preserved. New messages are added with an empty `msgstr`, and changed
messages are marked fuzzy. Run this command regularly, for example before each release.

## 7. Check translation coverage

```bash
hb i18n stats
```

prints the raw per-catalog statistics (translated, fuzzy and untranslated messages), one
`LC_MESSAGES` catalog after the other. The output is unchanged from `sphinx-intl stat`, so it
is suitable for scripts.

```bash
hb i18n stats-summary
```

aggregates the numbers per language and adds an `ALL` row with the overall percentage.

```{note}
Both commands exit with code 1 while any catalog has fuzzy or untranslated messages. This is
intentional, so a CI job can fail until the translation is complete. Do not read it as a
tool error.
```

## 8. Build in a specific language

```bash
hb html -l de
```

The `--language` / `-l` option overrides `DOC__LANGUAGE` for this one build and does not change
`.hermesbaby`. The result goes into a language-specific folder, here `html/de` in the build
directory. The option is available for `html`, `text`, `pdf`, `html-live` and `pdf-live`.

For a live preview in German:

```bash
hb html-live -l de
```

To publish all languages, build each one in turn:

```bash
hb html -l en
hb html -l de
```

```{note}
`hb publish` reads from the `html` folder of the build directory and does not add a language
subfolder by itself. Check the result of your language builds before publishing.
```

## Command reference

| Command                           | Purpose                                                                |
|-----------------------------------|------------------------------------------------------------------------|
| `hb i18n gettext [--partly] [-v]` | Extract messages into `.pot` files (diagnostic)                        |
| `hb i18n update-po [-l LANG]...`  | Extract messages and create or refresh `.po` files; keeps translations |
| `hb i18n stats`                   | Raw per-catalog coverage                                               |
| `hb i18n stats-summary`           | Coverage aggregated per language, with an `ALL` row                    |
| `hb html -l LANG`                 | Build for one language without changing the configuration              |
